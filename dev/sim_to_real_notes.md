## 2. 確かめた事実（2026-11-03）

出どころは、作成に使った環境に取得した PX4 v1.17.0 のソース（`~/PX4-Autopilot`、タグ `v1.17.0`）の中の文書 `docs/en/` とソース、導入済みの Nav2（apt の版。1.3.13）のヘッダ、この教材の手順書である。GitHubでの対応は `https://github.com/PX4/PX4-Autopilot/blob/release/1.17/docs/en/<パス>`。

### 2-1. SITLでGazeboが受け持つもの（PX4の側）

- `src/modules/simulation/gz_bridge/GZBridge.cpp`: PX4のモジュール `gz_bridge` が、Gazeboの通信の仕組み（gz-transport）で、IMU・磁気・気圧・GPS（navsat）とLiDARを購読し、モーターの回転数の指令を `/<model>/command/motor_speed` へ出す（前のセッションで確かめた）。
- 同じファイルの `subscribeLaserScan`: パラメータ `SIM_GZ_EN_LIDAR` が有効のとき、`/world/<world>/model/<model>/link/link/sensor/lidar_2d_v2/scan` を購読する。`laserScanCallback` が、機体の向きの区画に詰め直して、uORBの `obstacle_distance` を出す（`MAV_FRAME_BODY_FRD`、`MAV_DISTANCE_SENSOR_LASER`）。下向きのLiDARの模型（`/link/lidar_sensor_link/sensor/lidar/scan`）は、別の関数 `laserScantoLidarSensorCallback` が読む。
- `src/drivers/distance_sensor/`: 実機の距離センサのドライバが約20個ある（`lightware_sf45_serial`・`tfmini`・`lightware_laser_serial`・`lightware_laser_i2c`・`vl53l1x`・`ll40ls` 等）。
- `src/drivers/distance_sensor/lightware_sf45_serial/lightware_sf45_serial.hpp`: 回転式のLiDAR（LightWare SF45）のドライバは、シリアルで読み、`gz_bridge` と同じuORBの `obstacle_distance` を出す。
- → **SITLの `gz_bridge` は、PX4の中でドライバの代わりをしている**。uORBのトピックより先（推定・制御・衝突防止）は、実機と同じコードである。

### 2-2. 衝突防止（`docs/en/computer_vision/collision_prevention.md`）

- マルチコプターの Position mode（`MPC_POS_MODE` が加速度ベース）の中だけで働く。オフボード制御の間は働かない（フェーズ5の1節・7節に書いた内容と一致）。
- センサの値の出どころは、コンパニオンコンピュータ、MAVLinkの距離センサ、フライトコントローラにつないだ距離センサ、その組み合わせ。
- 箱から出してすぐ使えるのは、LightWare SF45（v1.14以降。320°）と、Lanbao PSK-CM8JL65-CC5（製造終了）。ほかの距離センサは、ドライバに向きと視野を設定する改造が要る。
- 距離の値が0.5秒届かないと、警告を出して水平の速さの目標を0にする。5秒届かないと Hold に移る。
- 遅れ（`CP_DELAY`）: フライトコントローラに直接つないだセンサの遅れは0とみなせる。外の画像処理の遅れは0.2秒にもなる。機体が速さの目標に追い付く遅れは、ふつう0.1〜0.5秒。
- コンパニオンコンピュータから距離を渡す方式（MAVLinkの `OBSTACLE_DISTANCE`）は、「今は試験されていない（元のプロジェクトは保守されず、保管された）」と書かれている。
- Gazeboの `x500_lidar_2d` で試せる、と書かれている（この教材のフェーズ5の構成）。

### 2-3. オフボード制御の途絶（`docs/en/flight_modes/offboard.md`・`docs/en/config/safety.md`）

- PX4は、外の制御のプログラムが生きている証拠として、`OffboardControlMode`（または MAVLink の目標のメッセージ）が2Hzより速く届くことを求める。
- 下回ると、`COM_OF_LOSS_T` の時間の後に Offboard を抜け、`COM_OBL_RC_ACT` の動作（Position・Altitude・Manual・Return・Land・Hold）をする。
- `COM_RC_OVERRIDE`（スティックを動かすと Position mode に移る）は、**オフボードのモードでは既定で無効**。
- **気づいたこと**: PX4が見張るのは合図が届くかどうかだけで、目標の中身が正しいかは見ない。フェーズ6の `replan_flight` は、自分のタイマー（0.1秒ごと）で合図を送り続けるので、計画器やLiDARの中継が止まっても、PX4は気づかない。経路が無くなったときは、その場で止まる作り（`choose_target`）だが、LiDARの値の新しさは見ていない。計画器は最後に覚えた地図で計画し続ける見込み（確かめていない）。
- Nav2のコストマップには、センサの値が届く間隔を見張る仕組みがある（`/opt/ros/jazzy/include/nav2_costmap_2d/nav2_costmap_2d/observation_buffer.hpp` の `expected_update_rate`。0は制限なし）。フェーズ6では使っておらず、届かなくなったときの計画器の動きは確かめていない。
- キルスイッチ（`config/safety.md`）: すべてのモーターの出力をすぐ止める（飛んでいれば落ちる）。既定では、5秒以内に戻せば再開し、過ぎるとディスアームする（`COM_KILL_DISARM`）。
- ジオフェンス（同じ文書）: `GF_MAX_HOR_DIST`・`GF_MAX_VER_DIST` の円柱。0で無効。

### 2-4. PX4とROS 2のつなぎ方（`docs/en/middleware/uxrce_dds.md`）

- クライアントがPX4の上で、エージェントがコンパニオンコンピュータの上で動く。PX4が対応する経路は、UDPとシリアルだけ。
- PX4の側の設定: `UXRCE_DDS_CFG`（`TELEM2`・`Ethernet`・`Wifi` 等）。シリアルなら、そのポートの `_BAUD`（例: `SER_TEL2_BAUD`）。ドメインの番号は `UXRCE_DDS_DOM_ID`。名前空間は `UXRCE_DDS_NS_IDX`（`uav_0` 等）。
- エージェントの例: Raspberry Pi の UART0 なら `MicroXRCEAgent serial --dev /dev/AMA0 -b 921600`（文書の例。逐語で載せる場合は出典に書く）。
- SITLでは、PX4がクライアントをlocalhostのUDPの8888番で自動で起動する（この教材のT3の `udp4 -p 8888`）。
- 時刻合わせ `UXRCE_DDS_SYNCT`: 既定で有効。

### 2-5. 時刻（`docs/en/ros2/user_guide.md` の「ROS, Gazebo and PX4 time synchronization」）

- ROS 2とPX4の時刻合わせは、既定ではuXRCE-DDSが自動で行う。状態は `/fmu/out/timesync_status` で見られる。
- **フライトコントローラの上のクライアントと、コンパニオンコンピュータの上のエージェントの組み合わせでは、時刻のずれ・ずれの増え方・通信の遅れが計算され、自動で補われる。これが本来の使い方**、と書かれている。
- Gazeboのシミュレーションでは、`gz_bridge` がシミュレーションの1歩ごとにPX4の時刻を設定する（Gazebo Classicのロックステップとは違う、と書かれている）。ROS 2の側を Gazebo の時計に合わせる方法（`use_sim_time` と `UXRCE_DDS_SYNCT` を false）もある。
- → この教材のフェーズ6-1の2-4節の `override_timestamps_with_wall_time` は、Gazeboの時計とPCの時計がずれるSITLだけの対処。実機のLiDARのドライバは、ふつうコンパニオンコンピュータの時計で時刻を付けるので要らない（ドライバの挙動は一般論で、確かめていない）。
- **確かめた（2026-11-03）**: フェーズ0の4節の「PX4とGazeboはロックステップで動く」「止められない」は、`docs/en/sim_gazebo_gz/index.md` の「The simulators are run in lockstep … the GZBridge sets the PX4 time on every sim step」「Lockstep cannot be disabled on Gazebo」と一致する。user_guide.md の「Gazebo Classicのロックステップとは違う」は、仕組み（時刻の渡し方）の違いを言うもので、矛盾しない。フェーズ0は直さない。

### 2-6. コンパニオンコンピュータ（`docs/en/companion_computer/index.md`）

- フライトコントローラはNuttXの上のPX4で、飛行と安全の中核のコードを受け持つ。コンパニオンコンピュータはふつうLinux。速いシリアルかEthernetでつなぎ、MAVLinkかuXRCE-DDSで話す。地上局やクラウドとの通信は、ふつうコンパニオンコンピュータを経由する（MAVLink Router等）。
- **Ethernetは、フライトコントローラが対応していれば、勧められるつなぎ方**。
- 文書が挙げる例: 大きく電力の大きいもの ModalAI VOXL 2・NXP NavQPlus・Nvidia Jetson TX2・Intel NUC・Gigabyte Brix。小さく電力の小さいもの Raspberry Pi。Pixhawkを差し込む台の基板 ARK Jetson PAB Carrier・Holybro Pixhawk Jetson Baseboard・Holybro Pixhawk RPi CM4 Baseboard。一体のもの Auterion Skynode・ModalAI VOXL 2。
- 選ぶ観点: 費用・重さ・消費電力・準備のしやすさ・要る計算の力。
- `companion_computer_peripherals.md`: コンパニオンコンピュータとPixhawkをつなぐには、FTDIのUSBの変換器が最も一般的。

### 2-7. GPSの無い場所での位置（`docs/en/computer_vision/visual_inertial_odometry.md`・`docs/en/ros/external_position_estimation.md`）

- VIO（カメラと慣性センサで、出発点からの位置・向き・速さを推定する）は、屋内や橋の下など、GPSが無いか当てにならない場所で使う。
- PX4は、値の出どころを問わない（決まったインターフェースで届けばよい）。設定は `EKF2_EV_CTRL`・`EKF2_HGT_REF` 等。GPS・気圧・距離センサの融合を `EKF2_GPS_CTRL` 等で止められる。
- uXRCE-DDS では `/fmu/in/vehicle_visual_odometry` で渡せる（既存の間章の5-2節で、`dds_topics.yaml` で確かめ済み）。
- カメラは振動に弱いので、柔らかく取り付ける（防振のフォーム等）ことが勧められている。

### 2-8. 試験（`docs/en/test_and_ci/test_flights.md`・`docs/en/test_cards/`）

- 標準の試験飛行の手順（テストカード）: MC_01 手動のモード、MC_02 完全な自動、MC_03 自動と手動の混在、MC_04 フェイルセーフ、MC_05 屋内（手動）、MC_06 屋内（オプティカルフロー）、MC_07 低い位置のオプティカルフロー、MC_08 DShotのESC、MC_09 VIO、MC_10 オプティカルフローとGPSの混在。
- MC_04: 送信機の途絶・通信の途絶・電池の低下を試す。飛行の前に、各フェイルセーフの動作が Return であることなどを確かめる。
- 文書の冒頭に「このページは古いかもしれない」との注意がある（版ごとの文書の共通の表示）。

### 2-9. 確かめていない一般論（書くなら、確かめていない旨を添える）

- LiDAR自身がROS 2のメッセージを出すことは、ふつう無い。メーカー独自の形式のバイト列を、シリアル・USB（中身はシリアル）・Ethernet（UDP）で出し、ドライバが読む。
- コンパニオンコンピュータにつなぐセンサのROS 2のドライバの例: Slamtec RPLIDAR の `sllidar_ros2`、北陽電機の `urg_node`、Intel RealSense の `realsense-ros`、Livox の3次元のLiDARのドライバ。
- micro-ROS（マイコンの上でROS 2のノードを動かす）はあるが、LiDARの製品がそれで直接ROS 2に出すのは一般的ではない。
- 2DのLiDARは、機体が傾くと測る面も傾く（加速や減速のときに、床や天井を壁と見ることがある）。測るのは1つの高さだけ。
- 起動の自動化: Nav2の `lifecycle_manager`（`autostart`）、launchのファイル、OSの起動時に動かす仕組み（systemd）。
- 記録: PX4のULog（SDカード）と、ROS 2の rosbag2（`ros2 bag record`）。
- ネットワーク: `ROS_DOMAIN_ID` と、Jazzyの `ROS_AUTOMATIC_DISCOVERY_RANGE`。無線のLANの上でのDDSの通信量。
- 飛ばす場所の法規と許可（国・場所ごとに違う）。既存の間章と同じく扱わず、公式の情報で確かめるよう書く。
