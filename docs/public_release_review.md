# 公開前レビューの観点

このリポジトリを更新して公開する（GitHubへpushする）たびに使う点検の観点をまとめた。学習者向けの手順書ではなく、リポジトリを保守するための文書である。このリポジトリは開発の初期からPublicで公開しているので、pushはそのまま公開になる。形は、親プロジェクト（[ros2MinimalPhysicalAi](https://github.com/SanghunIm1991/ros2MinimalPhysicalAi)）の同名の文書を写し、このプロジェクトの内容に合わせた。

- 対象: リポジトリが追跡しているすべてのファイル（`git ls-files`）と、全履歴（すべてのブランチ・コミット）
- 実施の目安: **pushの前に毎回**。手順書をいくつか更新したときにも行う
- 観点は3つ: 1節「機密情報の流出」、2節「権利侵害」、3節「リンク先が意図どおりか」
- 各節は、コマンドで機械的に拾う「機械点検」と、読んで判断する「目視点検」に分けている。機械点検で何も出なくても、目視点検は省かない
- 結果は、末尾の4節「実施記録」に1行ずつ追記する。指摘と対応の判断は [`docs/qa_log.md`](qa_log.md) にも記録する

コマンドは、リポジトリの直下で実行する。どれもファイルを読むだけで、変更や外部への送信はしない（外部への通信を伴うのは、3-2節で外部リンクを開いて確かめるときだけ）。

## 1. 機密情報の流出

### 1-1. 見る観点

| 観点 | 具体例 | 主な置き場所 |
|---|---|---|
| 認証情報 | APIキー、トークン、パスワード、秘密鍵 | 全ファイル・全履歴 |
| コミットの名義 | author・committerの名前とメールアドレスが、GitHubのnoreplyアドレス（`<数字>+<ユーザー名>@users.noreply.github.com`）になっているか | `git log` のメタデータ |

### 1-2. 機械点検

コミットの名義を一覧する（全ブランチ・全履歴）。

```bash
git log --all --format='%an <%ae> | %cn <%ce>' | sort | uniq -c
```

**見方**: 各行の左が件数、`|` の左がauthor、右がcommitter。どちらもnoreplyアドレスになっていれば問題ない。Claudeの関与はコミットメッセージの `Co-Authored-By` トレーラーで示す規約なので、名義の欄に `noreply@anthropic.com` が出ることは無い想定。noreply以外のアドレスが1件でもあれば、該当コミットを調べる。

追跡中のファイルと全履歴から、メールアドレスの形の文字列を拾い、想定済みのもの（noreply・ダミーの `example.com`）を除く。

```bash
git grep -nIE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' | grep -vE 'users\.noreply\.github\.com|noreply@anthropic\.com|@example\.(com|org)|git@github\.com'

git log --all -p | grep -oE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' | grep -vE 'users\.noreply\.github\.com|noreply@anthropic\.com|@example\.(com|org)|git@github\.com' | sort | uniq -c
```

認証情報らしい語と、ユーザー名を含むパスを、今の版と全履歴（過去の版で足した行）から拾う。

```bash
git grep -nIiE 'api[_-]?key|secret|token|passw(or)?d|BEGIN [A-Z ]*PRIVATE KEY|ghp_[A-Za-z0-9]|github_pat_|sk-[A-Za-z0-9]{10}'

git log --all -p | grep -E '^\+' | grep -iE 'api[_-]?key|secret|token|passw(or)?d|BEGIN [A-Z ]*PRIVATE KEY|ghp_[A-Za-z0-9]|github_pat_|sk-[A-Za-z0-9]{10}' | sort | uniq -c

git grep -nIE '/home/[a-z][a-z0-9_-]*|[A-Za-z]:\\+Users\\+|/mnt/c/Users/'

git log --all -p | grep -E '^\+' | grep -E '/home/[a-z][a-z0-9_-]*|[A-Za-z]:\\+Users\\+|/mnt/c/Users/' | sort | uniq -c
```

追跡してはいけないものが入っていないかを見る（`.gitignore` の項目とそろえている。`.gitignore` を変えたら、ここも変える）。

```bash
git ls-files | grep -E '^(notes|ws|ros2_ws|px4_ws|build|install|log|PX4-Autopilot|Micro-XRCE-DDS-Agent|\.vscode|\.idea)/|^\.claude/settings\.local\.json$|(^|/)(Thumbs\.db|Desktop\.ini|\.DS_Store)$|\.(env|pem|key|tar|vhdx|ulg)$|rosbag2_'
```

**見方**: メールアドレスの2つのコマンドと、追跡してはいけないもののコマンドは、何も表示されなければ問題ない。認証情報とパスのコマンドは、説明文の中の一般的な語（「パスワード」、`/home/<ユーザー名>` のような伏せ字、この文書のコマンドそのもの）にも当たるので、1件ずつ読んで、実際の値や実在のユーザー名が書かれていないかを判断する。GitHubのアカウント名は、上の正規表現では拾えないので、アカウント名そのもので `git grep -n` して、出てきた箇所を目視で判断する（著作権者の表示とリポジトリのURLは問題ない）。

### 1-3. 目視点検

- [`CLAUDE.md`](../CLAUDE.md)・[`docs/handoff_from_parent.md`](handoff_from_parent.md) に、PCの利用状況やスペックの制約、PCの扱いへの注意の言及が、公開してよい書き方で残っているか。
- `docs/` の実測のPCの値（RAM・ディスク容量・PX4のビルドの時間など）が、公開してよい範囲か。
- [`docs/qa_log.md`](qa_log.md) に新しく足した行に、アカウント名・実メール・PC固有の情報・個人の練習環境の状態（`notes/` に書くべき内容）が入っていないか。
- 前回の実施以降に足した画像があれば、1枚ずつ開いて写り込みを確かめる。

## 2. 権利侵害

### 2-1. 見る観点

| 観点 | 具体例 | 主な置き場所 |
|---|---|---|
| 公式ドキュメントの抜粋 | 抜粋した箇所に、帰属表示（出典・ライセンス・改変の有無）が残っているか。抜粋が必要な範囲に留まっているか。PX4のユーザーガイド・PX4のソースと付属のサンプル（`px4_ros_com` 等）・Micro XRCE-DDS Agentの文書は、使う前にライセンスを確かめ、結果を [`docs/qa_log.md`](qa_log.md) に残す | 環境構築の手順書、各手順書 |
| 各ページの出典注記 | 公式の文書と同等のコマンド・APIの使い方を含むページに、出典（元にしたものとそのライセンス）と「逐語の転載でない」旨の注記があるか | `docs/` の手順書 |
| 模型のファイル | PX4に付属するGazeboの機体・ワールドの模型（SDF・メッシュ等）を、リポジトリに含めていないか（読者が各自の導入済みのファイルを使う・写す形にする） | `git ls-files` |
| 引用の範囲 | ツールの出力（型の定義の表示、`pxh>` の表示、警告の文面など）が、説明に必要な範囲に留まり、出典があるか | 各手順書の「期待する結果」 |
| 図 | `docs/img/` の図が自作のもので、第三者の図・ロゴ・埋め込み画像が混ざっていないか。スクリーンショットに写っている第三者の画面が `LICENSE` の第三者の一覧に載っているか | `docs/img/` |
| サンプルコード | 公式のサンプルや他のリポジトリのコードを、丸ごと転載していないか | 各手順書のコードブロック |
| 第三者のファイル | データシート・PDF・フォント・画像など、ライセンスが不明なファイルが追跡されていないか | `git ls-files` |
| リポジトリのライセンス | `LICENSE` の3節（第三者の著作物）の一覧が最新か。サンプルコードが使うパッケージに、コピーレフト（GPL等）のものが加わっていないか | [`LICENSE`](../LICENSE)、`README.md` のライセンスの節 |

### 2-2. 機械点検

追跡しているファイルのうち、Markdown・SVG・Gitの設定・ライセンスのファイル以外のものを一覧する。

```bash
git ls-files | grep -vE '\.(md|svg)$|^\.git(attributes|ignore)$|^LICENSE(-APACHE-2\.0)?$|^docs/img/phase1_gazebo\.png$'
```

模型のファイルの形（SDF・メッシュ等）が追跡されていないかを見る。

```bash
git ls-files | grep -iE '\.(sdf|world|dae|stl|obj|fbx|glb|gltf|urdf|xacro)$'
```

SVGに、外部の画像や外部へのリンクが埋め込まれていないかを見る（`docs/img/` を作ってから）。

```bash
git grep -nE '<image|href="https?:' -- 'docs/img/*.svg'
```

**見方**: 1つ目と2つ目は、何も表示されなければ問題ない。自作のサンプルのファイル（自作のワールド等）や、中身を確かめた画像を足したら、確かめた上で、名前を指定して除外に加える（拡張子ごと除外しない）。3つ目も、何も表示されなければ問題ない。出典の注記の有無は、手順書ができたら、親プロジェクトの同名の文書の2-2節と同じ形のコマンドをここに足す。

### 2-3. 目視点検

- 前回の実施以降に足した・大きく直した節で、公式の文書や記事の文章をほぼそのまま写していないか（要約・自分の言葉での再構成になっているか）。
- 足したサンプルコードが、公式のサンプルのコードと一致しすぎていないか（仕様・変数名・構成まで同じなら、書き直すか出典を明記する）。
- 2-1節の表の帰属表示・出典の注記が、文書の書き換えで消えていないか。

## 3. リンク先が意図どおりか

### 3-1. 見る観点

| 観点 | 具体例 |
|---|---|
| 文書間のリンク | 相対パスのリンクの先のファイルが実在するか |
| 参照の書き方 | 他の文書への参照が、パスを `` ` `` で囲むだけでなくリンクになっているか（GitHubで読む前提のため） |
| 親プロジェクトへの参照 | 親プロジェクトの手順書へのリンク（GitHubの絶対URL）の先と、参照している節の番号・見出しが今もあるか（親プロジェクトの手順書は今後も更新される） |
| 節の参照 | 本文の「N節」「N-M節」などの参照が、現在の見出しの番号と中身に合っているか |
| 外部リンクの実在 | 外部のURLがリンク切れになっていないか |
| 外部リンクの中身 | リンク先が使う版（ROS 2 Jazzy、PX4の使う版、Gazebo Harmonic）に固定されているか、リンクの文言と中身が合っているか |

### 3-2. 機械点検

文書間のリンクの先が実在するかを確かめる（`README.md` と `docs/` の文書の、リンクの `(...)` の中の、`http` で始まらないものを対象にする。`CLAUDE.md` は読者向けの文書ではないので対象にしない）。

```bash
python3 - <<'PY'
import pathlib, re
bad = 0
for md in [pathlib.Path('README.md'), *sorted(pathlib.Path('docs').glob('*.md'))]:
    for n, line in enumerate(md.read_text(encoding='utf-8').splitlines(), 1):
        for target in re.findall(r'\]\(([^)\s]+)\)', line):
            if re.match(r'[a-z]+:', target):
                continue
            path = (md.parent / target.split('#')[0]).resolve()
            if not path.exists():
                bad += 1
                print(f'{md}:{n}: {target}')
print(f'リンク切れ: {bad}件')
PY
```

外部リンクの実在は、この環境から外部へアクセスして確かめる必要がある。アクセスする前に、対象のドメインの一覧（下のコマンド）を見て、見慣れないドメインが無いかを確かめる。

```bash
grep -ohE '\]\(https?://[^/)]+' docs/*.md README.md | sort | uniq -c | sort -rn
```

**見方**: 1つ目は `リンク切れ: 0件` だけが表示されれば問題ない。2つ目は、件数の多い順にドメインが並ぶ。docs.ros.orgはボット対策でコマンドやツールからの取得に失敗するため、Web検索か、文書の原稿のリポジトリで実在を確かめる。GitHubの `blob` のリンクは、同じパスを `raw.githubusercontent.com` で開いて200が返るかで確かめる。

### 3-3. 目視点検

- 節を足した・繰り下げた・消した文書について、その文書と、その文書を参照している他の文書の「N節」を読み直す。
- 親プロジェクトの手順書を参照している箇所について、参照先の節が今もあるかを確かめる。
- 外部リンクのうち、前回の実施以降に足したものは、リンク先を開いて、リンクの文言・版・内容が本文の説明と合っているかを確かめる。
