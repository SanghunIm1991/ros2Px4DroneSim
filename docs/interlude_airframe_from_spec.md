## 0. 学習目標と完了条件

この章を読み終えたら、次ができる状態を目指す。

1. 新しい機体を作るときに触る値を、「Gazeboの模型」「PX4の値」「両方をそろえる値」に分けて挙げられる（1節・8節）。
2. 公開された諸元から、模型の質量・慣性・ローターの位置・推力の係数・最大の回転数を計算し、諸元に無い値を推定で決めて、そのことを書き分けられる（2節・3節）。

4. 飛ばした機体の揺れに、モーターへの指令のばらつきで気づき、ゲインを下げても直らないときに、測定の遅れ（ジャイロのフィルタ）を疑って直せる（6節・7節）。
5. 試した値を片付け、本編の機体の値に戻せる（10節）。

## 1. 機体を作るときに触るもの

自分で組み立てたドローンを、シミュレーションで先に飛ばしてみたい。そう考えたとき、手元にあるのは、製品のページに書かれた重さや寸法と、部品の型番くらいである。シミュレーションの機体は、前の間章で見たとおり、Gazeboが計算する**模型**と、PX4が使う**機体の設定（パラメータの値）**の組でできている。新しい機体では、その両方を、手元の諸元から埋めていくことになる。

埋める値は、次の3つに分かれる。

| 区分 | 値の例 | 決め方 |
|---|---|---|
| Gazeboの模型だけ | 質量・慣性・形・推力の係数・最大の回転数・プロペラの空気抵抗 | 諸元から計算する。無いものは推定する |
| PX4の値だけ | 制御のゲイン・ジャイロのフィルタ・ホバリングの推力 | 似た機体の値を出発点にし、飛ばして直す |
| 両方をそろえる値 | ローターの位置と回る向き、モーターの指令の範囲 | 模型とPX4で、同じ値・同じ並びにする |

「両方をそろえる値」がずれると、機体は飛ばない（ひっくり返る・浮かない）。「PX4の値だけ」がずれると、飛ぶが、揺れたり、遅れたりする。この章は、この順に、模型を作り（2〜4節）、そろえる値を合わせ（5節）、飛ばして直す（6・7節）。

## 2. 諸元を集める

### 2-1. 公開されている値

QAV250は、Holybroが販売している、250クラス（対角のモーターの間が250mm前後）のカーボンのフレームのキットである。PX4の文書には、このキットの旧い組み合わせ（販売終了。モーター DR2205 KV2300、4S 1300mAh の電池）の組み立ての例と、その機体の設定（4052番）がある。この章では、**今販売されているキット**を題材にする。製品のページと予備の部品のページ（出典）に書かれている値は、次のとおりである（2026-11-23に確かめた）。

| 値 | 公開されている値 | 出どころ |
|---|---|---|
| キットの重さ（電池を含まない） | Basicのキット 440g（フライトコントローラ・GPS・テレメトリを含む） | 製品のページ |
| ホイールベース | 250mm | 製品のページ・予備の部品のページ |
| フレームだけの重さ | 148g | 予備の部品のページ |
| モーター | 2207 KV1950（1個 35.2g、線を含む） | 製品のページ（モーターの推力の表の画像） |
| プロペラ | 5インチのプラスチック（型は書かれていない） | 製品のページ |
| ESC | 2〜4Sの電池に対応 | 予備の部品のページ |
| 推奨の電池 | 4S 2200〜3000mAh（キットに含まれない） | 製品のページ |

表の中の言葉を確かめておく。**4S**は、リチウムポリマーの電池の小さな電池（セル。1つ約3.7V）を4つ直列にしたもので、公称14.8Vである（6Sは6つで約22.2V）。**mAh**は、電池に蓄えられる電気の量の単位で、大きいほど長く飛べるが重くなる。**ESC**（electronic speed controller）は、フライトコントローラの指令を受けて、モーターに流す電気を調整し、回転の速さを変える装置である。**スロットル**は、モーターへの指令の大きさ（0〜100%）である。

**KV**は、モーターに1V加えたときの、負荷の無い回転数（rpm）である。KV1950のモーターに4Sの電池（公称14.8V）をつなぐと、負荷が無ければ毎分約28,900回転する。

モーターの推力の表には、プロペラ4種類（T5143S・T5146・T5147・T5150）ごとに、スロットル50〜100%での推力（g）・回転数（rpm）・電流などが載っている。ただし、**試験の電圧は約22〜23.6V（6S）**で、キットのESCが対応する4Sより高い。

### 2-2. 足りない値と、推定の仕方

公開されている値だけでは、模型は作れない。足りない値は、次のように推定した。推定は、外れていても機体が飛ぶ範囲で、理由を一文で言えるものにする。

| 足りない値 | 推定した値 | 推定の理由 |
|---|---|---|
| 電池の重さ | 250g | 推奨の範囲の下の 4S 2200mAh の、一般的な重さ。自分の電池があれば、その重さに置き換える |
| プロペラの型 | T5146（推力の表の中間） | 型が書かれていないので、表の4種類の中間を選んだ |
| 4Sでの最大の回転数 | 2,146rad/s | 無負荷の回転数 KV×14.8V に、6Sの表の100%での「負荷時の回転数 ÷ 無負荷の回転数」（T5147の100%の行: 30,076rpm ÷ (1950×21.86V) ≈ 0.71）を掛けた。4Sは負荷が軽いので、本当はもう少し速い見込み |
| プロペラ1枚の重さ | 4g | 5インチのプラスチックのプロペラの、一般的な重さ |
| 反トルクの係数・プロペラの空気抵抗・モーターの応答の時間 | x500の値（空気抵抗は直径の比の2乗で割り引いた） | 公開の資料に無い。x500の模型の値を借りた |
| 電池と電子部品の形 | 0.11×0.04×0.05m の箱 | 電池の大きさを目安にした |

## 3. 模型の値を計算する

### 3-1. 推力の係数

GazeboのモーターのプラグインMulticopterMotorModel（前の間章の2-1節）は、プロペラの推力を **推力 [N] = 係数 × 角速度 [rad/s]²** で計算する。この係数（`motorConstant`）は、推力の表から計算できる。T5146の50%の行は、推力 748.66g・回転数 19,750rpm である。

- 推力: 0.74866kg × 9.80665 = 7.342N
- 角速度: 19,750 × 2π ÷ 60 = 2,068rad/s
- 係数: 7.342 ÷ 2,068² = 1.72×10⁻⁶

100%の行（1,798.78g・30,751rpm）で計算しても1.70×10⁻⁶で、ほぼ同じになる。推力が回転数の2乗に比例する、というプラグインの式が、この表によく当てはまる。この章では1.71×10⁻⁶とした。参考に、x500の模型の係数は8.55×10⁻⁶で、大きなプロペラほど係数が大きい。

係数は電圧によらない（プロペラの性質で決まる）見込みなので、6Sの表から求めた係数を、4Sの機体にそのまま使う。電圧で変わるのは最大の回転数で、それは2-2節で推定した。

### 3-2. 重さと、ホバリングの見積もり

全体の重さは、キット440g＋電池250g＝0.69kgである。ホバリングでは、4つのモーターの推力の合計が重さとつり合うので、1つのモーターの推力と回転数は、次のようになる。

- 1つのモーターの推力: 0.69 × 9.80665 ÷ 4 = 1.69N
- そのときの角速度: √(1.69 ÷ 1.71×10⁻⁶) ≈ 995rad/s（約9,500rpm）
- 最大の推力（2,146rad/s）: 1.71×10⁻⁶ × 2,146² ≈ 7.9N。4つで、重さの約4.7倍

この「ホバリングで約995rad/s」が、6節でPX4の表示と見比べる、模型の予想の値になる。

### 3-3. 慣性とローターの位置

**慣性**（慣性モーメント）は、機体の回りにくさである。重さが同じでも、重さが外側にあるほど回りにくい。姿勢の制御の効き方に直接かかわるので、模型にとって大事な値である。この章では、機体を次の3つに分けて、それぞれの慣性を足した。

- 電池と電子部品: 箱（2-2節の寸法、残りの重さ 0.385kg）
- フレーム: 対角の2本の細い棒（148g）
- モーター: アームの先の4つの点（35.2g ずつ）

結果は、Ixx 1.62×10⁻³・Iyy 1.95×10⁻³・Izz 3.41×10⁻³ kg·m²（x軸は前、z軸は上）で、x500（0.022・0.022・0.040）の約1/14〜1/11である。小さな機体は、ずっと回りやすい。

**ローターの位置**は、ホイールベース250mmから、中心からモーターまで0.125m、X型の正方形として前後・左右に±0.0884m（0.125÷√2）とした。

## 4. 模型を書き出す

### 4-1. 書き出すスクリプト

3節の計算と、模型のファイルの書き出しを、1つのPythonのスクリプトにまとめる。値を変えたいとき（自分の電池の重さ等）は、先頭の定数を直して実行し直せばよい。センサ（加速度・ジャイロ・気圧・磁気・GPS）の部分は、自分のPCにあるx500の模型から読み込む。センサの種類と雑音の大きさは、x500と同じにした。

スクリプトと、5節の値の一覧を置くフォルダを、先に作る。

```bash
# T5
```

ファイル: `~/px4_ws/airframe_qav250/gen_qav250.py`

```python
"""QAV250の諸元から、Gazeboの模型（model.sdf と model.config）を計算して書き出す。"""
import math
import os
import xml.etree.ElementTree as ET

PX4 = os.path.expanduser('~/PX4-Autopilot/Tools/simulation/gz/models')
OUT = os.path.join(PX4, 'qav250')

# 諸元（出どころ: 製品のページ・予備の部品のページ・モーターの推力の表）と推定
MASS_KIT = 0.440        # Basicのキットの重さ（ページの値。電池を含まない）
MASS_BATTERY = 0.250    # 4S 2200mAh の電池（推定）
MASS_FRAME = 0.148      # フレームのキット（予備の部品のページ）
MASS_MOTOR = 0.0352     # モーター1個（推力の表の仕様）
MASS_PROP = 0.004       # プロペラ1枚（推定）
WHEELBASE = 0.250       # 対角のモーターの間の距離（ページの値）
K_THRUST = 1.71e-6      # 推力 = 係数 × 角速度² の係数（推力の表のT5146から計算）
KV, VOLT, LOAD = 1950, 14.8, 0.71   # 4Sの最大の回転数 = KV × 電圧 × 負荷の比（推定）
BOX = (0.11, 0.04, 0.05)            # 電池と電子部品をまとめた箱の寸法（推定）


def box_inertia(m, lx, ly, lz):
    """直方体の慣性（中心の周り）を返す。"""
    return (m * (ly**2 + lz**2) / 12, m * (lx**2 + lz**2) / 12, m * (lx**2 + ly**2) / 12)


def calc():
    """質量・慣性・ローターの位置・最大の回転数を計算する。"""
    r = WHEELBASE / 2
    p = r / math.sqrt(2)
    m_base = MASS_KIT + MASS_BATTERY - 4 * MASS_PROP
    m_box = m_base - MASS_FRAME - 4 * MASS_MOTOR
    box = box_inertia(m_box, *BOX)
    rod = MASS_FRAME * WHEELBASE**2 / 12           # フレームを対角の2本の棒として
    frame = (rod / 2, rod / 2, rod)
    motor = (4 * MASS_MOTOR * p**2, 4 * MASS_MOTOR * p**2, 4 * MASS_MOTOR * r**2)
    inertia = [a + b + c for a, b, c in zip(box, frame, motor)]
    w_max = KV * VOLT * LOAD * 2 * math.pi / 60
    return m_base, inertia, p, w_max


def x500_sensors():
    """読者のPCにあるx500の模型から、本体のセンサの要素を読み込む。"""
    tree = ET.parse(os.path.join(PX4, 'x500_base', 'model.sdf'))
    link = tree.getroot().find("./model/link[@name='base_link']")
    return '\n'.join(ET.tostring(s, encoding='unicode') for s in link.findall('sensor'))


def rotor(n, x, y, direction, w_max):
    """n番目のローターの部品・関節・モーターのプラグインを返す。"""
    ip = (MASS_PROP * 0.012**2 / 12, MASS_PROP * 0.127**2 / 12, MASS_PROP * (0.127**2 + 0.012**2) / 12)
    return f'''
    <link name="rotor_{n}">
      <pose>{x:.4f} {y:.4f} 0.03 0 0 0</pose>
      <inertial>
        <mass>{MASS_PROP}</mass>
        <inertia><ixx>{ip[0]:.3e}</ixx><iyy>{ip[1]:.3e}</iyy><izz>{ip[2]:.3e}</izz></inertia>
      </inertial>
      <visual name="rotor_{n}_visual">
        <geometry><cylinder><radius>0.0635</radius><length>0.002</length></cylinder></geometry>
      </visual>
    </link>
    <joint name="rotor_{n}_joint" type="revolute">
      <parent>base_link</parent>
      <child>rotor_{n}</child>
      <axis><xyz>0 0 1</xyz><limit><lower>-1e+16</lower><upper>1e+16</upper></limit></axis>
    </joint>
    <plugin filename="gz-sim-multicopter-motor-model-system" name="gz::sim::systems::MulticopterMotorModel">
      <jointName>rotor_{n}_joint</jointName>
      <linkName>rotor_{n}</linkName>
      <turningDirection>{direction}</turningDirection>
      <timeConstantUp>0.0125</timeConstantUp>
      <timeConstantDown>0.025</timeConstantDown>
      <maxRotVelocity>{w_max:.1f}</maxRotVelocity>
      <motorConstant>{K_THRUST:.3e}</motorConstant>
      <momentConstant>0.016</momentConstant>
      <commandSubTopic>command/motor_speed</commandSubTopic>
      <motorNumber>{n}</motorNumber>
      <rotorDragCoefficient>1.193e-05</rotorDragCoefficient>
      <rollingMomentCoefficient>1.479e-07</rollingMomentCoefficient>
      <rotorVelocitySlowdownSim>10</rotorVelocitySlowdownSim>
      <motorType>velocity</motorType>
    </plugin>'''


def main():
    """模型のファイルを書き出し、計算した値を表示する。"""
    m_base, inertia, p, w_max = calc()
    # ローターの番号・位置・回る向きは、x500と同じ並び（Gazeboの座標: x前・y左）
    rotors = [(p, -p, 'ccw'), (-p, p, 'ccw'), (p, p, 'cw'), (-p, -p, 'cw')]
    body = f'''<?xml version="1.0" encoding="UTF-8"?>
<sdf version="1.9">
  <model name="qav250">
    <pose>0 0 0.05 0 0 0</pose>
    <link name="base_link">
      <inertial>
        <mass>{m_base:.4f}</mass>

      <visual name="body">
        <geometry><box><size>{BOX[0]} {BOX[1]} {BOX[2]}</size></box></geometry>
      </visual>
      <visual name="arm_a">
        <pose>0 0 0 0 0 0.7854</pose>
        <geometry><box><size>{WHEELBASE} 0.012 0.004</size></box></geometry>
      </visual>
      <visual name="arm_b">
        <pose>0 0 0 0 0 -0.7854</pose>
        <geometry><box><size>{WHEELBASE} 0.012 0.004</size></box></geometry>
      </visual>
      <collision name="body_collision">
        <pose>0 0 -0.015 0 0 0</pose>
        <geometry><box><size>{2 * p + 0.03:.4f} {2 * p + 0.03:.4f} 0.03</size></box></geometry>
      </collision>

    </link>{''.join(rotor(n, x, y, d, w_max) for n, (x, y, d) in enumerate(rotors))}

    os.makedirs(OUT, exist_ok=True)
    with open(os.path.join(OUT, 'model.sdf'), 'w') as f:
        f.write(body)
    with open(os.path.join(OUT, 'model.config'), 'w') as f:
        f.write('<?xml version="1.0"?>\n<model>\n  <name>qav250</name>\n  <version>1.0</version>\n'
                '  <sdf version="1.9">model.sdf</sdf>\n  <description>QAV250 made of simple shapes (learning example)</description>\n</model>\n')
    print(f'本体の質量 {m_base:.3f} kg（プロペラを足した全体 {m_base + 4 * MASS_PROP:.3f} kg）')
    print(f'慣性 Ixx {inertia[0]:.2e}  Iyy {inertia[1]:.2e}  Izz {inertia[2]:.2e} kg·m²')
    print(f'ローターの位置 ±{p:.4f} m、最大の回転数 {w_max:.0f} rad/s')
    print(f'書き出した: {OUT}')


if __name__ == '__main__':
    main()
```

このスクリプトで、一般的な模型の書き方から変えたところがある。

- **一般的な書き方**: 模型は、`model.sdf` を手で書く（前の間章の5-4節）か、CADのソフトから書き出す。
- **このサンプルで変えた理由**: 4つのローターは同じ形の繰り返しで、値は3節の計算で決まる。手で写すと、計算と模型の値が食い違いやすいので、計算と書き出しを1か所にまとめた。センサの部分を読み込むのは、PX4の模型の文を、この教材に写さないためでもある。
- **実務での目安**: 形の複雑な機体は、CADのソフトで形と慣性を求め、書き出した値を使うことが多い。値を計算で決めるときも、どの値をどこから決めたかを、ファイルの中に残しておく。

## 5. PX4の値を、模型に合わせる

### 5-1. 機体の設定の番号を借りる

この機体にも、前の間章の5-5節と同じく、PX4の機体の設定のファイルを作らない。x500の設定（4001番）を読み込むだけの番号を借り、模型の名前を環境変数で指定し、違う値は環境変数 `PX4_PARAM_<名前>=<値>` で渡す。PX4の起動のスクリプトは、この形の環境変数を見つけると、起動のたびに `param set` する。

借りる番号は、**4005番**（`gz_x500_vision`）にする。本編で使う4001番や4013番を借りないのは、片付けのためである。PX4は、機体の設定の番号が前回の起動と変わったときに、パラメータを既定の値に戻す（[間章: PX4の既定の設定を確かめる](interlude_px4_defaults.md) でも使った性質）。本編と違う番号を借りておけば、本編の機体で起動し直すだけで、この章で変えた値が既定に戻る（10節）。同じ番号を借りると、変えた値が本編の機体に残ってしまう。また、番号が変わらない間は、`PX4_PARAM_` で設定した値は保存され、次の起動にも残る。一覧から行を消しただけでは、その値は既定に戻らない（7-1節で戻し方を使う）。逆に言えば、4005番で起動した時点で、本編の機体で自分が変えた値（例: フェーズ5の `CP_DIST`）も既定に戻る。残したい値があれば、先に控えておく。

4005番は、中身が4001番を読み込むだけなので、x500のローターの位置やモーターの指令の範囲を既定に持つ。そこで、模型と合わせる値を、次の一覧で上書きする。

### 5-2. そろえる値の一覧

ファイル: `~/px4_ws/airframe_qav250/qav250.env`

```bash
# QAV250の模型と合わせる値（ローターの位置〈PX4はx前・y右〉と、モーターの指令の上限）
PX4_PARAM_CA_ROTOR0_PX=0.0884
PX4_PARAM_CA_ROTOR0_PY=0.0884
PX4_PARAM_CA_ROTOR1_PX=-0.0884
PX4_PARAM_CA_ROTOR1_PY=-0.0884
PX4_PARAM_CA_ROTOR2_PX=0.0884
PX4_PARAM_CA_ROTOR2_PY=-0.0884
PX4_PARAM_CA_ROTOR3_PX=-0.0884
PX4_PARAM_CA_ROTOR3_PY=0.0884
PX4_PARAM_SIM_GZ_EC_MAX1=2146
PX4_PARAM_SIM_GZ_EC_MAX2=2146
PX4_PARAM_SIM_GZ_EC_MAX3=2146
PX4_PARAM_SIM_GZ_EC_MAX4=2146
```

この12個は、模型を変えたら必ずそろえる値なので、以下「必須の12個」と呼ぶ。

**ローターの位置**（`CA_ROTOR<n>_PX`・`_PY`）は、模型の位置と同じ値にする。PX4の座標は前・右・下（FRD）、Gazeboの模型は前・左・上なので、左右の符号が逆になる（模型の `rotor_0` の y が −0.0884 なら、PX4の `CA_ROTOR0_PY` は +0.0884）。番号と回る向きは、x500と同じ並びにしたので、回る向きの値（`CA_ROTOR<n>_KM`）は4001番のままでよい。

**モーターの指令の上限**（`SIM_GZ_EC_MAX<n>`）は、見落としやすい。PX4は、モーターへの出力（0〜1）を、`SIM_GZ_EC_MIN`〜`SIM_GZ_EC_MAX` の値に直線で写し、その値を**回転の速さの指令（rad/s）として**Gazeboへ送る。4001番の上限は1000で、x500の模型の最大の回転数（`maxRotVelocity` 1000）と合わせてある。この上限のままQAV250を飛ばすと、指令は1000rad/sまでしか出ない。3-1節の係数では、1000rad/sの推力は1つで1.71N、4つで重さとほぼ同じ（約1.0倍）になり、機体はほとんど浮かない。模型の `maxRotVelocity`（2146）、PX4の `SIM_GZ_EC_MAX`、推力の係数は、**組で合わせる値**である。

`SIM_GZ_EC_MAX` の値の範囲は、パラメータの定義では1000までとされているが、`param set` は2146を受け付け、意図どおりに動いた（筆者が確かめた）。

`PX4_PARAM_` には、注意が1つある。PX4の起動のスクリプトが `PX4_PARAM_` を設定する時点では、機体の設定のファイルはまだ読まれておらず、各パラメータは定義の既定値である。シェルの `param set` は、今の値と同じ値を渡されると何もしない。そのため、**定義の既定値と同じ値を渡すと記録されず、後で機体の設定のファイルが既定を変えていれば、そちらが効く**。この一覧の値は、どれも定義の既定値（0や1000）と違うので、問題ない。

## 7. 揺れを直す

### 7-1. まず、ゲインを下げてみる

PX4の姿勢の制御は、2段になっている。外側の**姿勢の制御**が、目標の傾きとのずれから「どれだけの速さで回ればよいか」を決め、内側の**角速度の制御**が、ジャイロで測った回転の速さを、その目標の速さに合わせるように、モーターの出力を決める。角速度の制御は、ずれの大きさに比例した力を出す **P**（比例）と、ずれが変わる速さに比例した力を出す **D**（微分。ずれが大きくなりそうなときに、先回りしてブレーキをかける）などを足し合わせる。PとDの強さを決める係数が、**ゲイン**（`MC_ROLLRATE_P`・`MC_ROLLRATE_D` 等。ROLLは左右の傾き、PITCHは前後の傾き）である。

細かい揺れを見ると、多くの人は、まず「制御が強すぎる」と考える。4005番のゲインは、x500（2kg）のための値で、QAV250（0.69kg、慣性は約1/14〜1/11）には強すぎるのではないか。PX4の4052番（旧いQAV250の設定）の角速度のPゲイン（`MC_ROLLRATE_P` 0.076・`MC_PITCHRATE_P` 0.082）は、4001番の既定（0.15）の約半分である。

値の一覧に、次の2行を足して起動し直す（T1で `pxh> shutdown` を打ってから、6-1節のT1のコマンドをもう一度実行する）。

```bash
PX4_PARAM_MC_ROLLRATE_P=0.076
PX4_PARAM_MC_PITCHRATE_P=0.082
```

筆者が試した結果は、**揺れは減らず、少し大きくなった**（7-3節の表）。角速度のDゲイン（`MC_ROLLRATE_D`・`MC_PITCHRATE_D`）だけを4052番の値（0.0012。既定は0.003）にしても、さらに悪くなった。制御が強すぎて揺れているなら、ゲインを下げれば揺れは減るはずなので、原因は「制御が強すぎる」ことだけでは説明できない。

試し終えたら、足した2行を一覧から消す。ただし、5-1節のとおり、同じ4005番で起動し直しても、前の起動で設定した値は保存されて残る。7-2節で起動し直した後に、飛ばす前に、T1で既定に戻す。

```bash
# T1
pxh> param reset MC_ROLLRATE_P MC_PITCHRATE_P

pxh> param show MC_ROLLRATE_P
```

**期待する結果**（`param show` の表示の抜粋）:

```text
x   MC_ROLLRATE_P [551,1004] : 0.1500
```

4001番の既定の0.15に戻っていればよい（角括弧の中の番号は、パラメータの通し番号で、読まない）。

### 7-2. 測定の遅れを疑う

ゲインを下げても直らない揺れの原因として、PX4の文書（フィルタの調整の文書）が挙げているのが、**制御の遅れ**である。制御の遅れは、機体が乱れてからモーターが反応するまでの時間で、ジャイロ（角速度のセンサ）の値をなめらかにするフィルタ（**ローパスフィルタ**。速い変化を取り除くフィルタ）も、この遅れを生む。文書によると、ジャイロのフィルタの遮断の周波数（`IMU_GYRO_CUTOFF`）と遅れの目安は、30Hzで約8ms、60Hzで約3.8ms、120Hzで約1.9msで、既定の値は質の低い機体でも動くように控えめにしてある。Dゲインの計算には、もう1つのフィルタ（`IMU_DGYRO_CUTOFF`）がかかる。

既定は、`IMU_GYRO_CUTOFF` 40Hz・`IMU_DGYRO_CUTOFF` 20Hzである。4052番は、120Hz・45Hzにしている。値の一覧に、次の2行を足して（7-1節の2行は消して）起動し直し、7-1節の `param reset` でゲインを既定に戻してから飛ばす。

```bash
PX4_PARAM_IMU_GYRO_CUTOFF=120
PX4_PARAM_IMU_DGYRO_CUTOFF=45
```

もう一度離陸させ、止まったところで、T1でモーターへの指令を見る。

```bash
# T1
pxh> listener actuator_outputs

pxh> listener hover_thrust_estimate
```

**期待する結果**（抜粋。値は1回ごとに変わる）:

```text
pxh> listener actuator_outputs
TOPIC: actuator_outputs 4 instances
...
    output: [994.00000, 992.00000, 991.00000, 994.00000, 0.00000, ...]
pxh> listener hover_thrust_estimate
...
    hover_thrust: 0.42297
...
    valid: True
```

4つの指令が991〜994にそろい、3-2節の見積もり（約995rad/s）とほぼ一致する。ゲインは既定のままで、揺れは消えた。`hover_thrust` も、モーターの出力（0〜1）が約0.42のときの値で、指令の値 150＋(2146−150)×0.42 ≈ 990 と合う。模型が、3節の計算どおりに動いていることも、ここで確かめられる（6-2節の0.40は、揺れのために少しずれていたと考えられる）。

なぜ小さな機体ほどフィルタの遅れが効くのかは、次のように考えられる（筆者の推定）。慣性が小さい機体は、同じ乱れでも速く傾く。測定が数ms遅れる間に、傾きが進んでしまい、遅れて反応した制御が、かえって揺れを育てる。7-1節でDを下げると悪くなったことも、この見方と合う。Dは、ずれの変わり方から先回りする働きで、遅れを補う側に効くので、弱めると遅れの影響が大きくなる。Pを下げても悪くなった理由は、確かめていない。

### 7-3. 試した結果のまとめ

筆者が、同じ方法（離陸・30秒のホバリング・北へ5mの移動）で測った値である。「傾き」は、ホバリング中の傾きの最大と、移動の指示から7秒後以降の傾きの範囲で、揺れが残っていると大きくなる。

| 試した値（必須の12個に加えて） | ホバリングの傾き | 移動の後の傾き | モーターへの指令（1回） |
|---|---|---|---|
| 既定のまま（6節） | 1.55° | 1.2〜1.6° | 830・798・1351・258 |
| 角速度のPゲインだけ4052番の値 | 2.02° | 1.3〜1.6° | 1227・870・210・1022 |
| 角速度のDゲインだけ4052番の値 | 2.83° | 1.8〜2.6° | 1504・150・535・1120 |
| ジャイロのフィルタだけ4052番の値 | **0.29°** | **0.12〜0.33°** | **994・992・991・994** |
| 4052番の値をすべて | 0.33° | 0.15〜0.38° | （見ていない） |
| 参考: x500（4001番、既定のまま） | 0.37° | 0.2〜0.3° | （見ていない） |

フィルタの2つを変えるだけで、4052番の値をすべて使ったときと同じくらいに安定した。この機体では、4052番のほかの値（ゲイン・`MC_AIRMODE`・推力の曲線の値 `THR_MDL_FAC` 等）は、安定して飛ぶためには要らなかった。

この章では1つずつ値を変えたが、変えるたびに起動し直すので時間がかかる。違いが多いときは、半分ずつ入れて絞り込む方法もある。

## 9. 実際の機体の開発では

この章は、試すだけなので、PX4のファイルを書き換えない方法（番号を借り、値は環境変数で渡す）を使った。実際の機体の開発では、次のように進めることが多い。

- **機体の設定のファイルを作る**: 空いている番号で、機体の設定のファイルを作り、PX4の機体として登録する（前の間章の7節の手順）。この章の値の一覧は、そのファイルに `param set-default` の形で書く。そうすれば、5-2節の `PX4_PARAM_` の注意も当てはまらない。
- **諸元を測る**: 重さは秤で、慣性は吊り下げて揺らす方法などで測る。モーターとプロペラの推力は、推力の試験台で、使う電池の電圧で測る。この章で推定した値の多くが、測った値に置き換わる。
- **調整は実機で確かめる**: シミュレーションで安定しても、実機には、フレームの振動・センサの雑音・モーターの遅れがあり、フィルタやゲインの最適な値は変わる。PX4には、飛びながらゲインを自動で調整する機能（**オートチューン**。Multicopter Auto-Tuning）と、フィルタを調整する手順の文書がある。この章では、名前の紹介だけにする。

## 11. まとめ

- 新しい機体では、Gazeboの模型・PX4の値・両方をそろえる値の3つを埋める。そろえる値（ローターの位置、モーターの指令の上限）がずれると、機体は飛ばない。
- 公開された諸元だけでは足りない。足りない値は、理由を一文で言える推定で埋め、推定であることを書いておく。
- 推力の表から、模型の推力の係数を計算できる。ホバリングの回転数の見積もりは、飛ばしたときのモーターへの指令と見比べる「答え」になる。
- 揺れたときに、ゲインを下げるとは限らない。この機体では、原因はジャイロのフィルタの遅れで、フィルタを変えるだけで直った。
- 本編と違う番号を借りておけば、本編の機体で起動するだけで値が戻る。

## 12. 確かめの問い

**問い1**: 5-2節の一覧から `SIM_GZ_EC_MAX<n>` の4行を消して起動すると、何が起きるか。

<details>
<summary>答え</summary>

モーターへの指令が、4001番の上限の1000rad/sまでしか出ない。3-1節の係数では、1000rad/sの推力は4つで約6.8Nで、機体の重さ（約6.8N）とほぼ同じなので、離陸の指示をしても、ほとんど浮かないか、ゆっくりしか上がらない（5-2節）。
</details>

**問い2**: 自分の電池が4S 3000mAh（約330g）だった。4節のスクリプトのどこを変え、6-2節で見比べるホバリングの回転数の見積もりはどう変わるか。

<details>
<summary>答え</summary>

`MASS_BATTERY` を0.330にして実行し直す。全体は0.77kgになり、1つのモーターの推力は 0.77×9.80665÷4 ≈ 1.89N、回転数は √(1.89÷1.71×10⁻⁶) ≈ 1,051rad/s になる（3-2節の計算）。重くなった分、ホバリングの回転数が上がる。
</details>

**問い3**: 7-1節で、ゲインを下げるほど揺れが大きくなった。この結果から、「ゲインが強すぎる」という仮説を捨てられるのはなぜか。

<details>
<summary>答え</summary>

ゲインが強すぎて揺れているなら、ゲインを下げると揺れは減るはずである。下げて揺れが増えたので、ゲインの強さだけでは説明できず、別の原因がある、と考えられる。この章では、次に制御の遅れ（ジャイロのフィルタ）を疑い、変えたら直った（7-2節）。Dを下げて悪くなったことは、Dが遅れを補う働きをすることと合う（7-2節の最後の段落。筆者の推定）。
</details>

## つまずきやすい点

- **離陸の指示をしても、ほとんど浮かない**: `SIM_GZ_EC_MAX<n>` を値の一覧に入れ忘れている（問い1）。T1で `pxh> param show SIM_GZ_EC_MAX1` を打ち、2146になっているかを確かめる。
- **離陸の直後にひっくり返る**: 模型とPX4で、ローターの位置か回る向きが合っていない。PX4の `CA_ROTOR<n>_PY` は、模型の y と符号が逆になる（5-2節）。
- **値の一覧の値が効いていない**: その値が、パラメータの定義の既定値と同じではないかを確かめる（5-2節の最後の段落）。T1で `pxh> param set <名前> <値>` を打てば、起動の後からでも設定できる。
- **本編の機体に、この章の値が残っている**: `PX4_PARAM_` の環境変数を、括弧の外で `export` していないかを確かめる（6-1節）。T1を閉じて開き直せば消える。
- **`Spawning Gazebo model` の後に機体が現れない**: 4-2節の `gz sdf -k` で、模型のファイルを点検する。x500の模型が無い・読めないと、スクリプトがセンサを読み込めずに止まる。
