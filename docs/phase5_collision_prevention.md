# フェーズ5: 組み込みの衝突防止を試す

[学習計画](learning_plan.md) のフェーズ5の手順書。PX4に組み込まれている衝突防止（Collision Prevention）を有効にし、QGCの画面の上の操縦桿（仮想ジョイスティック）で、機体を壁に向かって飛ばす。機体が壁の手前で減速して止まること、壁に沿う向きへ入力を少し曲げること、LiDARが見ていない向きへは動けないことを確かめ、組み込みの衝突防止にできることと、できないことを整理する。ここで見た「できないこと」が、フェーズ6で、自分で経路を計画し直す理由になる。プログラムは書かない。

- 想定環境: [フェーズ4](phase4_lidar.md) を終えたWSL2のUbuntu 24.04
- 所要の目安: 1コマ
- 必須の範囲: 1〜8節（9節の課題は任意）
- 前提（親プロジェクト）: なし

> **この手順書の位置づけ**: フェーズ4で見たLiDARの値をPX4自身が使う道（フェーズ4の2-1節の、5°ごとの区画にまとめる処理）を、実際に働かせる。ROS 2は使わない（フェーズ4のRViz2を並べて見ると、壁との距離が分かりやすい）。
>
> **期待する結果の出どころ**: （作成中）パラメータの名前・既定値・働きは、PX4 v1.17のソースと文書で確かめた。仮想ジョイスティックの設定の名前と既定値は、QGroundControl v5.1.5の文書と設定の定義で確かめた。起動・設定・飛行の表示と機体の動きは想定したもので、まだ動かしていない。実際に動かした表示に差し替える予定。

## 0. 学習目標と完了条件

この手順書を終えると、次のことができるようになる。

1. Position modeで、操縦の入力が機体の動きにどうつながるかを説明できる（2節）。
2. 衝突防止のパラメータを、PX4のシェルで設定し、元に戻せる（3節・4節・8節）。
3. QGCの仮想ジョイスティックで、機体をPosition modeで飛ばせる（5節・6節）。
4. 組み込みの衝突防止ができることと、できないことを説明できる（6節・7節）。

**完了条件**（すべて満たしたら完了）:

1. 壁に向かって前へ飛ばし続けても、機体が、設定した距離（2m）より壁に近づかない（6-2節）。
2. LiDARが見ていない真後ろへは、操縦しても機体が動かないことを確かめる（6-4節）。
3. 組み込みの衝突防止ができないこと（経路を計画し直さない、Position modeのような手動のモード以外では働かない）を、7節の表を見ずに説明できる。

## 1. 全体像

フェーズ4の2-1節で見たとおり、PX4は、GazeboのLiDARのトピックを自分でも受け取り、270°の距離を5°ごとの区画にまとめて、「障害物までの距離」として持っている。衝突防止は、この距離を使って、操縦の入力から作った動きの目標を、ぶつからないように直す仕組みである。

| 順 | 何が起きるか | どこで |
|---|---|---|
| 1 | LiDARの値を、5°ごとの区画の距離にまとめる | PX4（Gazeboとの中継の部分） |
| 2 | 操縦桿の入力を、動きの目標（加速度の目標）にする | PX4（Position mode） |
| 3 | 最も近い障害物へ向かう成分を、近いほど強く弱める（既定の設定では、約10mより近いと効き始める）。入力の向きを少し曲げることもある | PX4（衝突防止） |
| 4 | 直した目標で、機体を動かす | PX4（位置と速度の制御） |

3の衝突防止は、2のPosition modeのように、操縦桿の入力を加速度の目標にする手動のモードの中でだけ働く。オフボード制御（フェーズ3）や、Hold・Return・Takeoff・Landなどの自動のモードでは働かない（7節。厳密には、Landの最中に操縦桿で位置を少し直す処理でも使われる）。

この手順書では、2つのターミナルを使う（フェーズ4の6節のRViz2を並べて見る場合は、フェーズ4のT3とT5も使う）。

| ターミナル | 動かすもの | 仮想環境 `~/px4-venv` |
|---|---|---|
| T1 | PX4のシミュレーション（`make px4_sitl gz_x500_lidar_2d_walls`）とPX4のシェル | 使う |
| T2 | QGroundControl | 使わない |

## 2. Position modeと操縦の入力

### 2-1. Position mode

Position modeは、操縦する人の入力で機体を動かす飛行モードの1つで、手を離すとその場に止まる（フェーズ0の5-2節）。これまでのフェーズで使ったHoldやTakeoffは、PX4が自分で動きを決める自動のモードで、操縦の入力を使わなかった。

操縦の入力は、2本の操縦桿（スティック）で行う。この手順書で使うQGCの仮想ジョイスティックの初めの設定では、次のように割り当てられる（ラジコンの送信機で一般的な「モード2」の割り当て）。

| 操縦桿 | 上下 | 左右 |
|---|---|---|
| 左 | 上昇・下降（中央で今の高さを保つ） | 機首の向きを回す |
| 右 | 前進・後退（機体から見て） | 右・左へ動く（機体から見て） |

PX4 v1.17の既定のPosition modeは、「加速度ベース」（パラメータ `MPC_POS_MODE` が4）である。右の操縦桿を倒すと、倒した量に応じた加速度の目標になり、機体は速度を上げていく。操縦桿を中央に戻すと、ブレーキがかかり、その場に止まる。衝突防止は、この加速度ベースのPosition modeでだけ使える（既定のままでよい）。

### 2-2. 操縦の入力の出どころ

Position modeは、操縦の入力が届いていないと選べない。実機では、ラジコンの送信機やゲーム用のコントローラを使う。PX4のシミュレーションの既定の設定では、操縦の入力を、MAVLink（フェーズ0の6節）でQGCから受け取るだけになっている（パラメータ `COM_RC_IN_MODE` が1）。この手順書では、QGCの画面に操縦桿を表示する仮想ジョイスティックを使う。仮想ジョイスティックは、表示している間、操縦桿の位置を、毎秒25回、PX4に送り続ける。

仮想ジョイスティックを使って離陸した後、飛んでいる間に操縦の入力が途切れると（既定では0.5秒）、Position modeに限らず、HoldやTakeoffの間でも、PX4はフェイルセーフ（フェーズ0の9-2節）に移り、既定の設定ではReturnで離陸した地点へ戻る（パラメータ `NAV_RCL_ACT` が2）。QGCを閉じると、地上局とのつながりが切れたことでも、同じくReturnになる。飛行中は、仮想ジョイスティックを無効にしたり、QGCを閉じたりしない。

また、PX4の既定の設定では、自動のモード（Takeoff・Hold等）の間に操縦桿を動かすと、操縦する人が操縦を取り戻したとみなして、Position modeに切り替わる（パラメータ `COM_RC_OVERRIDE` が1）。自動のモードで飛ばしている間は、操縦桿に触れない。

## 3. 衝突防止のパラメータ

衝突防止は、PX4 v1.17の既定では無効である。次のパラメータで設定する。

| パラメータ | 既定値 | 意味 | この手順書 |
|---|---|---|---|
| `CP_DIST` | −1 | 障害物に近づいてよい最小の距離（m）。負の値で、衝突防止を無効にする | 2にする |
| `CP_DELAY` | 0.4 | センサの値の遅れと、速度の目標に機体が追いつくまでの遅れ（秒）。止まるまでの距離の見積もりに使う | 既定のまま |
| `CP_GUIDE_ANG` | 30 | 入力の向きの左右、この角度（°）の範囲に、障害物の少ない向きがあれば、そちらへ曲げてよい | 既定のまま |
| `CP_GO_NO_DATA` | 0 | 1にすると、センサの値が無い向きへも動ける | 既定のまま |

`CP_DIST` の距離は、センサ（LiDAR）から測った距離であり、機体の外側やプロペラの先からの距離ではない。x500のプロペラの先は、機体の中心から約0.4m外にあるので、2mにすれば、壁とプロペラの間は1.5m以上残る。実機では、さらに余裕を持たせる。

## 4. 起動して、衝突防止を有効にする

PX4のシミュレーションは、フェーズ4と同じ、LiDAR付きの機体と壁のワールドで起動する。

```bash
# T1
source ~/px4-venv/bin/activate

cd ~/PX4-Autopilot

make px4_sitl gz_x500_lidar_2d_walls

# T2
cd ~/qgc

./QGroundControl-x86_64.AppImage
```

**期待する結果**（想定）: フェーズ4の3-2節と同じ（壁のワールドに、LiDAR付きの機体が現れ、T1に `Ready for takeoff!` が出る）。

T1でEnterを押して `pxh>` のプロンプトを出し、衝突防止の最小の距離を2mにする（`pxh>` はプロンプトなので打たない。フェーズ1の1節）。

```text
pxh> param set CP_DIST 2
```

**期待する結果**（想定）:

```text
  CP_DIST: curr: -1.0000 -> new: 2.0000
```

`curr` が設定する前の値（既定の−1）、`new` が設定した値である。何も表示されない場合は、前に設定した2が保存されていて、すでに2になっている（同じ値を設定しても、何も表示しない）。

PX4のシミュレーションは、変えたパラメータを、PX4のソースのビルドのフォルダの中のファイルに保存し、次に起動したときにも読み込む。そのため、`CP_DIST` は、PX4を起動し直しても2のままになる。この手順書の最後（8節）で、元の−1に戻す。

パラメータは、QGCでも見たり変えたりできる（**Q** のアイコン → **Vehicle Configuration** → **Parameters** で、`CP_DIST` を探す）。

## 5. 仮想ジョイスティックを表示する

QGCで、仮想ジョイスティックを有効にする。

1. 左上の **Q** のアイコンを押し、**Application Settings** を開く。
2. **General** のタブの、**Virtual Joystick** の欄にチェックを入れる。
3. 地図の画面（Fly View）に戻る。

**期待する結果**（想定）: 地図の画面の左下と右下に、丸い操縦桿が1つずつ表示される。左の操縦桿の丸は、上下の中央にある（指を離すと中央に戻る設定が、初めから有効になっている）。

## 6. 壁に向かって飛ばす

### 6-1. 離陸して、Position modeにする

QGCで、フェーズ1の5-1節と同じように機体を離陸させる（初めの10 ftのままでよい）。止まったら、上の帯の飛行モードの表示（**Hold**）を押し、出てきた一覧から **Position** を選ぶ。

**期待する結果**（想定）: 飛行モードの表示が **Position** になる。操縦桿に触れていなければ、機体はその場に止まったままである。

機体は東を向いている（フェーズ1の3節）。前には、フェーズ4の3-1節の壁1が、LiDARから約4.4m先にある。左（北）には、壁2が約4.5m先にある。

### 6-2. 前の壁に向かって飛ばす

右の操縦桿を、上へ半分ほど倒したままにする（左の操縦桿には触れない）。

**期待する結果**（想定）: 機体は前（東）へゆっくり進み、壁1に近づくほど遅くなって、LiDARから壁までが2m（`CP_DIST`）より遠い位置（ソースから見積もると2.5〜3m付近）で、ほとんど進まなくなる。操縦桿を上へ倒し続けても、2mより近くへは行かない。操縦桿を中央に戻しても、機体はその場に止まっている。

思ったより手前から遅くなるのは、衝突防止が、壁へ向かう加速度を、壁までの距離から `CP_DIST` を引いた残りの2乗に比例して弱めるためである（既定の設定では、約10mより近いと弱め始め、残りが0に近づくほど急に弱める）。

衝突防止を無効にしたままだと、同じ操作で、機体は壁にぶつかる（9節の課題1）。

止まったまま、右の操縦桿を、左下か右下へ斜めに倒す（真下から45°以上外す）と、機体は斜め後ろへ、壁から離れる向きに動ける（壁から離れる向きの加速度は弱められない）。まっすぐ下（真後ろ）へ倒しても動かない。その理由は6-4節で見る。

### 6-3. 壁に沿う向きへ曲げる

壁1の手前で止まった状態で、右の操縦桿を、右上（前と右の間）へ倒す。

**期待する結果**（想定）: 機体は前へは進まず、壁1に沿って右（南）へ動く。壁にまっすぐ向かう成分は止められ、壁に沿う成分だけが残るためである。入力の向きのすぐ横（`CP_GUIDE_ANG` の30°以内）に、障害物の少ない向きがあると、衝突防止は、入力の向きを少しそちらへ曲げる。

### 6-4. LiDARが見ていない向き

機体を壁1から離して、周りの空いた位置に戻す（右の操縦桿を左下へ斜めに倒して北西へ動かす、またはQGCの **Go to location** で原点の近くへ戻す。Go to locationを使うと飛行モードがHoldになり、移動の間は操縦桿に触れない（2-2節）。機首は移動の向き（西）を向く（フェーズ4の7節）。戻ったらPositionを選び直す）。そこで、右の操縦桿を真下（真後ろ）へ倒す。

**期待する結果**（想定）: 機体は、真後ろへはほとんど動かない。LiDARは前を中心に270°しか測っておらず、真後ろの90°には距離の値が無い。衝突防止は、入力の向きに値が無いと、「見えない障害物があるかもしれない」とみなして、加速度の目標を0にする（`CP_GO_NO_DATA` が0）。入力が真後ろから少し外れていると、`CP_GUIDE_ANG` の範囲で値のある向き（斜め後ろ）へ曲げて動くことがある。左の操縦桿を左右に倒して機首の向きを回してから進めば、その向きへは動ける。

## 7. 組み込みの衝突防止にできること、できないこと

| できること | できないこと |
|---|---|
| 操縦の入力で障害物に近づいても、決めた距離より近づかないように減速して止める | 障害物の向こうの目的地へ、回り道を探して進む（経路を計画し直す） |
| 入力の向きを、30°以内で、障害物に沿う向きへ少し曲げる | Position modeのような手動のモード以外（オフボード制御・Hold・Return・Takeoff・Land・ミッション）で働く |
| センサの値が無い向きへの動きを止める | センサの面の外（LiDARの水平な面より上や下）の障害物を見つける |

組み込みの衝突防止は、「操縦する人が障害物にぶつけないように、入力を直す」仕組みである。どこへ行くかを決めるのは操縦する人で、PX4は、決めた向きの動きを弱めたり、少し曲げたりするだけである。また、フェーズ3のオフボード制御で飛ばしているときは、衝突防止は働かない。フェーズ3のノードの経由点の間に壁があれば、機体は壁にぶつかる。

そこでフェーズ6では、ROS 2のノードが、フェーズ4のLiDARの値から障害物を見つけ、壁を避ける経由点を計画し直して、オフボード制御で飛ばす。

## 8. 止めて、元に戻す

QGCの **Land** で着陸させる（フェーズ1の5-3節）。ディスアームしたら、T1で、衝突防止を元の無効に戻す。

```text
pxh> param set CP_DIST -1
```

**期待する結果**（想定）:

```text
+ CP_DIST: curr: 2.0000 -> new: -1.0000
```

行の先頭の `+` は、設定する前の値が既定と違い、保存されていたことを示す。戻すのを忘れると、次に起動したときにも衝突防止が有効のままになる。フェーズ3のノードの飛行（オフボード制御）には影響しないが、LiDARの無い機体（`gz_x500`）でPosition modeを使うと、距離の値が届かないので水平に動けず、5秒後にHoldに切り替わる（つまずきやすい点）。

QGCの **Application Settings** の **Virtual Joystick** のチェックを外す（フェーズ6では使わない。地上で外すぶんには問題ない）。QGCのウィンドウを閉じ、T1のPX4のシミュレーションを Ctrl+C で止める。

## 9. 課題（任意）

1. `CP_DIST` を−1のまま、6-2節と同じ操作をして、機体が壁にぶつかることを確かめる（ぶつかった後は、PX4のシミュレーションを止めて起動し直す）。衝突防止が何をしていたかを、6-2節の結果と比べて説明する。
2. 衝突防止を有効にしたまま、QGCの **Go to location** で、壁1の向こう側（東へ8m）を指す。機体がHoldのモードで壁にぶつかることを確かめ、7節の表の「手動のモード以外では働かない」を確かめる。移動の間は操縦桿に触れない（触れるとPositionに切り替わり、衝突防止が働く。2-2節）。ぶつかった後は、PX4のシミュレーションを起動し直す。
3. `CP_GUIDE_ANG` を0にして（`pxh> param set CP_GUIDE_ANG 0`）、6-3節と同じ操作をする。入力の向きが曲げられなくなり、壁に沿って動く速さが落ちることを確かめたら、30に戻す。
4. フェーズ4の5節と6節の手順で、`parameter_bridge` とRViz2を並べて起動し、6-2節で止まったときの壁の点の直線が、2mより遠い位置にあることを確かめる。

## つまずきやすい点

- **一覧から Position を選んでも、モードが変わらない**: 操縦の入力が届いていない。仮想ジョイスティックが表示されているか（5節）を確かめる。QGCの画面とT1に、拒まれた理由が表示される。
- **Position modeにしたら、機体が下がっていく**: 左の操縦桿が中央にない。5節の設定で、左の操縦桿が中央に戻る設定になっているかを確かめる。
- **前へ倒しても、まったく動かない**: 衝突防止が、距離の値を受け取れていない。PX4は、距離の値が0.5秒届かないと水平の動きを止め、T1に `No obstacle data, not moving...` を表示し、5秒続くとHoldに切り替える。フェーズ4の機体（`gz_x500_lidar_2d_walls`）で起動しているかを確かめる。
- **操縦していないのに、飛行モードがPositionに変わった**: 自動のモードの間に操縦桿に触れると、Positionに切り替わる（2-2節の `COM_RC_OVERRIDE`）。
- **壁の手前で止まらずにぶつかる**: `CP_DIST` が設定されているか（`pxh> param show CP_DIST`）と、飛行モードがPositionかを確かめる。
